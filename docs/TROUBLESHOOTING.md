# 故障排查

遇到问题时，先看 GUI 状态栏或 CLI 的最后一段错误信息。导出器会保留 FFmpeg stderr 的尾部，通常比 Python 异常更接近根因。

## 找不到 FFmpeg 或 FFprobe

症状：

- GUI 状态栏显示“未找到 ffmpeg（仅预览）”。
- 导出报“未找到 ffmpeg（请放入 ffmpeg/ 目录或加入 PATH）”。
- 启动时提示没有 `ffprobe`，但仍可继续准备工程。

处理：

1. 确认项目根目录下是 `ffmpeg/ffmpeg.exe`，不是多套嵌套目录。
2. 或把 FFmpeg 的可执行文件目录加入 `PATH`，重新打开终端和 LVM。
3. 在同一个终端执行 `ffmpeg -version` 和 `ffprobe -version`。

`ffprobe` 缺失时，时长探测会回退到 mutagen；这不能替代导出所需的 `ffmpeg`。

## 导出按钮不可用

GUI 只有在以下条件都满足时启用导出：

- 已完成一次资源准备；
- 工程配置了音频；
- 工程配置了 LRC。

封面和背景不是导出必需项。若文件路径看起来已填入但仍无法导出，检查文件是否存在、扩展名是否受支持，以及 LRC 是否至少包含一行合法时间戳和正文。

CLI 直接模式必须同时提供 `--audio` 与 `--lrc`：

```bash
python main.py export --audio music.wav --lrc lyrics.lrc --output result.mp4
```

## 预览没有画面或歌词

按顺序检查：

1. LRC 是否为 UTF-8 文本，行是否形如 `[00:12.30]歌词`。
2. 时间戳中的分钟、秒和小数部分是否为数字。
3. 是否误把没有时间戳的纯文本当作 LRC；这类行会被忽略。
4. 是否刚修改参数；资源准备需要短暂后台时间，状态栏会显示准备状态。
5. 是否把歌词放在第一行时间之前；第一行开始前，当前行索引为 -1，画面不会显示歌词。

GUI 的“媒体信息”会显示解析出的标题、艺术家、专辑、LRC 行数和封面尺寸。LRC 元数据优先，缺失字段才从音频标签读取。

## 双语歌词配对不正确

相邻两条歌词的时间差小于 0.05 秒时，第二条会被视为第一条的译文。配对依赖排序后的相邻顺序，因此建议这样写：

```lrc
[00:10.00]中文歌词
[00:10.00]Translated lyric
```

如果两种语言的时间差超过阈值，或者中间插入了另一条歌词，它们会被视为独立行。`[offset:]` 的单位是毫秒；负偏移会把时间向前移动，但不会产生负时间。

## Enhanced LRC 没有逐词高亮

这是当前范围限制，不是解析失败。程序会识别 `<mm:ss.xx>` 词级标签并保留词时间，但内置 `fade` 和 `scroll_list` 动画仍按整行渲染。

## 字体缺字、歌词太大或被截断

- 将覆盖 CJK 的 `.ttf`/`.otf` 放入项目 `font/` 目录。
- 在 GUI 的“歌词样式”页为主歌词和译文分别选择字体。
- 字号范围为 10–300；宽度超出歌词区域时程序会自动缩小、换行，最后才省略号截断。
- 字体文件名写入 `.kproj`，移动工程到另一台机器时也要带上字体文件，或者切回“系统默认”。

当前没有逐字 font fallback；同一行中缺字可能来自所选字体本身。

## 歌词颜色对比度不理想

自动取色有两套逻辑：封面用于提取动画主色/辅色，歌词区域对应的背景用于决定默认文字/描边对比度。它不会用整张封面的平均色代替歌词区域。

需要固定颜色时：

1. 在“色彩”页关闭自动取色并设置动画主色/辅色。
2. 在“歌词样式”页直接设置主歌词色、译文色和描边色。

“色彩”页中的描边备用值会写入工程；实际文字绘制使用“歌词样式”页的描边颜色。

## 音频无法播放

LVM 先使用 Qt Multimedia 播放。如果 Qt 后端不能解码某个容器或 FLAC，程序会尝试调用 FFmpeg 解码为 48 kHz、双声道、16-bit PCM，再交给 `QAudioSink`。

如果回退失败：

- 确认 `ffmpeg -version` 可执行；
- 确认音频文件本身能被 FFmpeg 读取：`ffmpeg -i input.flac -f null -`；
- 重新选择文件，避免工程保存了已经移动或删除的路径。

预览音频失败不一定表示视频无法导出；导出时仍会由 FFmpeg 重新读取音频，但源文件必须有效。

## 输出时长或帧数不对

默认帧数为 `round(duration × fps)`。时长来源按以下顺序尝试：

1. CLI 的 `--duration`；
2. `ffprobe`；
3. mutagen；
4. 没有可读音频时，以最后一行歌词时间加 5 秒估算。

快速测试时的 `--frames N` 会限制视频帧数，因此生成的 MP4 可能明显短于音频。正式导出时去掉这个参数。

如果音频时长元数据损坏，可以用 `--duration` 验证画面时长，但 FFmpeg 仍需要能够打开原始音频。

## 导出失败、卡住或产生临时文件

- 硬件编码器探测只在后台执行；启动 GUI 不会等待它完成。
- `auto` 首选 NVENC、AMF、QSV，失败后回退 `libx264`。硬件路径写帧失败也会完整重跑软件编码。
- 导出先写输出目录里的隐藏临时 MP4，完成后才替换目标文件，所以取消不会留下半成品，也不会覆盖已有成品。
- 如果程序在进程被强制终止后留下形如 `.<文件名>.<随机值>.mp4` 的文件，可确认没有导出进程后手动删除它们。

软件编码通常更慢但兼容性最好。想验证硬件路径，可在 GUI 输出页选择具体编码器，或在 CLI 使用：

```bash
python main.py export --kproj project.kproj --encoder libx264 --output result.mp4
```

## 颜色、分辨率或播放器兼容性问题

导出命令会明确写入：

- H.264 High Profile；
- `yuv420p`；
- BT.709 色彩空间、原色、传递函数；
- tv range；
- AAC 48 kHz 立体声；
- MP4 `+faststart`。

手动编辑 `.kproj` 的 `width`/`height` 时必须使用偶数。当前布局实现是 `landscape_mv`，默认 1920×1080；GUI 不提供竖屏布局控件。

## 工程打开失败或媒体丢失

- `.kproj` 必须是 UTF-8 合法 JSON；损坏 JSON 会提示解析失败。
- v1.0 的字符串动画格式会自动迁移到 v1.1，未知字段会忽略。
- 相对媒体路径以 `.kproj` 所在目录为基准，然后才尝试原始绝对路径。
- 移动工程时尽量保持工程与素材的相对目录结构，或打开后在“素材”面板重新选择文件并保存。

如果需要确认工程内容，可以直接打开 JSON，或使用：

```bash
python main.py export --kproj path/to/project.kproj --frames 1 --output check.mp4
```

## 报告问题时附带的信息

请尽量提供：

- 操作系统和 Python 版本；
- `pytest` 的失败摘要；
- `ffmpeg -version` 的版本行；
- 使用的输入格式（无需上传私人媒体）；
- CLI 完整错误尾部或 GUI 状态栏文本；
- 是否能用 `python main.py demo --frames 60` 重现。
